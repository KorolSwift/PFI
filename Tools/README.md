# Импорт контента

Скрипт `import_questions.py` собирает вопросы и задачи из Markdown-файлов
в `Content/seed_content.json` — тот формат, который читает приложение.

**Главное свойство: скрипт идемпотентен.** Запускай сколько угодно раз — повторный
импорт того же файла не создаст дублей и не сломает существующую базу.

---

## Как пользоваться

```bash
# Посмотреть, что произойдёт, ничего не меняя
python3 Tools/import_questions.py --dry-run

# Применить
python3 Tools/import_questions.py
```

Входные файлы берутся из `Content/incoming/*.md`, результат пишется
в `Content/seed_content.json`. Папка `Content/` в `.gitignore`: личная база вопросов
хранится локально и в репозиторий не входит.

Типичный цикл: дописать вопросы в файл → `--dry-run` → посмотреть отчёт → применить.

---

## Формат входного файла

```markdown
topic: Concurrency
subtopic: GCD
level: middle
tags: gcd, threads

## Что такое race condition?

Ответ в Markdown. Можно списки, таблицы, **выделение**.

```swift
let queue = DispatchQueue(label: "example")
```

## [junior] Что такое DispatchQueue?

Уровень в квадратных скобках переопределяет `level` из шапки для одного вопроса.
```

**Правила:**

| Что | Как |
|---|---|
| Шапка файла | Строки `topic:`, `subtopic:`, `level:`, `tags:`, `type:` до первого `##` |
| Новый вопрос | Начинается с `##` |
| Уровень для одного вопроса | `## [junior] Текст вопроса` — junior / middle / senior |
| Ответ | Всё от заголовка до следующего `##` |
| Комментарии | `<!-- ... -->` в шапке, в том числе многострочные |
| Задачи вместо вопросов | `type: task` в шапке; уровень означает сложность: easy / medium / hard |

Заголовки `##` внутри блоков ``` не считаются новыми вопросами — код с комментариями
не сломает разбор.

---

## Почему дубли не появляются

`id` вопроса вычисляется **детерминированно из текста вопроса**:

```
id = UUIDv5(фиксированный namespace, нормализованный текст)
```

Нормализация убирает регистр, пунктуацию и лишние пробелы. Поэтому
«Что такое ARC?» и «что такое арc» дадут **один и тот же id** — и попадут в базу один раз.

Следствия:

- Один и тот же вопрос из разных файлов импортируется однократно
- Правка ответа обновляет существующую запись, а не создаёт новую
- `id` и `order` при обновлении **не меняются** — а значит, не теряется прогресс
  пользователя, который на них завязан

**Что скрипт никогда не делает:** не удаляет существующие записи и не перенумеровывает
уже импортированные. Убрать вопрос из базы можно только вручную.

> ⚠️ Константа `NAMESPACE` в скрипте зафиксирована навсегда. Если её изменить,
> все существующие вопросы получат новые id и вся база задублируется.

---

## Что скрипт проверяет

В конце работы печатается отчёт с замечаниями:

- пустой ответ у вопроса
- непарный ``` — незакрытый блок кода
- неизвестный уровень
- дубли внутри самих входных файлов (с указанием, где встретился первый)
- отсутствие темы в шапке

Замечания не останавливают импорт — корректные записи всё равно попадут в базу.
