## Что такое ARC и чем он отличается от сборщика мусора?

**ARC** (Automatic Reference Counting) — это подсчёт ссылок, который компилятор
расставляет на этапе компиляции. Каждый объект хранит счётчик сильных ссылок;
когда счётчик доходит до нуля, объект немедленно освобождается.

Отличия от garbage collection:

- ARC работает **детерминированно**: момент освобождения предсказуем
- Нет отдельного потока сборщика и пауз на сборку
- Накладные расходы размазаны по коду, а не собраны в паузы
- Плата за это — **циклы сильных ссылок** ARC разрывать не умеет, это забота разработчика

```swift
final class Node {
    var next: Node?          // сильная ссылка
    weak var parent: Node?   // слабая — не увеличивает счётчик
}
```

## [junior] В чём разница между weak и unowned?

Обе ссылки не увеличивают счётчик, но ведут себя по-разному, когда объект исчез:

| | `weak` | `unowned` |
|---|---|---|
| Тип | всегда опциональный | неопциональный |
| Когда объект освобождён | становится `nil` | обращение — краш |
| Накладные расходы | больше (нужна запись в side table) | меньше |

**Правило выбора:** `unowned` — только когда ты уверена, что объект гарантированно
переживёт ссылку. Во всех остальных случаях `weak`. Сомневаешься — бери `weak`,
цена ошибки несопоставима.

## [senior] Что такое side table и зачем она нужна?

Side table — дополнительная структура, которая создаётся для объекта **лениво**,
только когда на него появляется первая слабая ссылка.

Причина существования: если бы `weak`-ссылки указывали прямо на объект, при его
освобождении их было бы негде занулить. Поэтому слабые ссылки указывают на side table,
а не на объект. Когда объект уничтожается, запись в side table помечается, и все
слабые ссылки при следующем обращении вернут `nil`.

Отсюда и разница в стоимости из предыдущего вопроса: `weak` требует лишней косвенности
и атомарных операций, `unowned` — нет.
